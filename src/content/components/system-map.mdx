<DocSection id="intent" index="01" title="Why it exists" description="Positioning is a relationship, not a percentage score.">

System Map communicates how four disciplines pull on one role or system. Its marker shows a deliberate position between those forces without pretending that product, engineering, AI, or design can be measured as a skill percentage.

**It should not become** a personality test, capability score, or evidence-free claim of equal expertise.

</DocSection>

<DocSection id="anatomy" index="02" title="Anatomy">

Two semantic axes create four named directions. One marker communicates the current position, while the supporting definition list explains what each direction means in this context.

</DocSection>

<DocSection id="usage" index="03" title="Usage">

```astro
<SystemMap
  axes={axes}
  position={{ x: 62, y: 39 }}
/>
```

Axis labels and descriptions must come from real product or role language. Position values tune composition; they are not published measurements.

</DocSection>

<DocSection id="variants" index="04" title="States">

- **Default** places one marker inside the four-axis field.
- **Mobile** reduces the field and reorganizes supporting definitions into two columns.
- Future multi-marker comparison is intentionally outside the current contract.

</DocSection>

<DocSection id="accessibility" index="06" title="Accessibility">

The visual field exposes a concise image description naming all axes. The supporting list repeats every axis with its contextual meaning, so color, geometry, and marker position are not the only sources of information.

</DocSection>

<DocSection id="performance" index="07" title="Performance">

Static HTML and CSS custom properties only. No charting library, canvas, layout observer, or client-side coordinate calculation.

</DocSection>
